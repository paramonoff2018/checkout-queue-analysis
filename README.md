# Анализ кассовых очередей (SQL + Power Query + Excel)

**Цель проекта:**  
На основе журнала кассовых операций двух магазинов определить периоды возникновения очередей, исключив ложные срабатывания.

**Данные:**
- `store_checkout_queues.csv` — логи чеков (время начала и окончания обслуживания)
- `store_stores.csv` — справочник магазинов

Данные содержат типичные для ритейла особенности: один чек может состоять из нескольких строк (по товарным позициям) с одинаковыми временными метками.

**Методология:**
1. **Объединение данных:** Power Query (и эквивалентный SQL) – левое соединение по `store_uuid`, фильтрация по двум магазинам.
2. **Агрегация до уровня чека:** для каждого уникального `checks_number` взято минимальное время начала и максимальное время окончания. Это устранило «шум» от множественных позиций внутри чека.
3. **Расчёт очереди:** чеки отсортированы по кассам и времени. Очередь фиксируется, когда время начала следующего чека **меньше** времени завершения текущего. Длительность очереди = (Макс_конец – След_начало) × 86400 секунд.
4. **Результат:** таблица с флагом «ОЧЕРЕДЬ» и длительностью ожидания в секундах. Все формулы Excel сохранены (не «пересохранены в значения») для аудируемости.

**Инструменты:**
- Power Query (M) – извлечение и очистка CSV с нестандартным форматированием
- Excel – сводные таблицы, расширенный редактор PQ, формулы `IF`, `AND`, математика дат
- SQL – запрос на `JOIN` и фильтрацию (аналог Power Query)
- Методология анализа временных рядов и предметное знание ритейла

**Файлы:**
- `case_checkout_queue_analysis.xlsx` – готовое решение (3 листа: Исходные данные, Готовый расчёт, Пояснение)

## Почему этот кейс важен
Показывает способность:
- работать с «грязными» сырыми данными (кавычки, разделители, плавающая структура CSV);
- не просто применять инструмент, а проектировать аналитическую методику;
- объяснять сложную логику простым языком (лист «Пояснение»);
- получать реалистичные результаты, избегая типичных ловушек (внутричековые артефакты).
